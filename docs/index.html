Built around one problem: mixed audio

Conversations rarely have just one voice. Every part of the app assumes more than one speaker from the start.

Record or import

Capture a conversation directly in-app, or import an existing WAV recording to analyze later.

Tell it how many speakers

Before separation runs, you choose how many people are in the recording — this drives the clustering and keeps results accurate for 2, 3, or more voices.

Automatic voice separation

A speaker-embedding model clusters the recording by voice using energy-based segmentation and cosine-similarity matching — no manual splitting required.

Review & tag speakers

See exactly which stretch of audio belongs to which voice, rename subjects, or manually adjust segments before moving on.

Per-speaker Voice Focus

Run analysis on the full recording, or narrow it to exactly one identified speaker's segments — the focus list is built from your actual tagged subjects.

Session history

Every processed session is saved with its charts and settings, so you can revisit or export results later.

  1. Set the expected speaker count

    A quick prompt before separation asks how many people are in the recording, so clustering has the right target.

  2. Voices are segmented automatically

    The recording is split into speech segments and each one is matched to a speaker using voice-embedding similarity — not simple loudness or pitch heuristics.

  3. Confirm or adjust

    Detected segments show up tagged by speaker immediately. Rename a subject, remove a bad segment, or add one manually.

  4. Choose what to analyze

    Run analysis on everything, or pick a single tagged speaker — the app filters to just that voice's segments before processing.

Runs entirely on-device

No audio leaves the phone. Inference runs locally through an embedded Python runtime and TensorFlow Lite.

Setup

Clone it, open it in Android Studio, and bring your own stress-classification model.

⚠️ The stress-detection model isn't included

Voice separation and speaker identification work out of the box — that model ships with the repo. The stress-classification model is not included, because the one used during development isn't the author's to redistribute.

To use the stress-detection features, supply your own TFLite classifier and drop it in app/src/main/assets/ as model.tflite, along with a matching scaler_values.json for feature normalization. Everything else — recording, separation, tagging, per-speaker Voice Focus — works without it. 

git clone https://github.com/FaaDzi/Voice-Stress-Detection.git
cd Voice-Stress-Detection

# Open in Android Studio, then:
#  1. Add your own model.tflite + scaler_values.json to app/src/main/assets/
#  2. Build & run on a device or emulator (API 26+)
./gradlew assembleDebug
